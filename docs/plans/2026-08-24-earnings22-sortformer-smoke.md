# Earnings-22 Sortformer 全库验证计划

## 研究问题

电话会议虽然可能出现很多参考说话人，但发言是否主要集中在1–2位主讲，从而使最多输出4位
speaker 的固定 Sortformer 仍能正确保留主讲？本实验只测固定 diarizer，不优化切片、预处理、
提示词或模型。

## 已冻结的数据画像

125场中116场超过4位参考说话人，分层为：`<=4` 9场、`5–8` 21场、`9–16` 39场、
`>16` 56场。由于部分上游强制对齐不完整，主分析只纳入对齐 token 比例至少80%、至少300秒
对齐词时长的会议。在此基础上，再要求 Top-2 发言占比至少60%，得到30场“少数主讲、长尾
参会人”目标组。全125场仍全部运行并报告结构结果，不能根据模型输出挑样本。

## 执行步骤

1. 将官方 MP3 确定性转换为单声道16 kHz PCM16 WAV，保留转换哈希收据。
2. 用锁定的 NeMo-Speech.cpp Q8 Sortformer、默认 streaming geometry 逐场运行，保存 RTTM、
   日志、耗时和哈希；失败可按会议续跑。
3. 全部 flight 完成后只判读一次参考：计算 Top-1/Top-2/长尾 speaker attribution error，
   并按参考人数分层汇总。
4. 同时报告固定1秒同 speaker 合并规则得到的 proxy DER；不得将其称为人工 RTTM DER。
5. 将 verdict、资源消耗、限制和下一决策归档到 `docs/checks/` 与 Wiki。

## 解释边界

若主讲指标通过，只能说明固定前端在“主讲占主导”的 Earnings-22 子群可用；不能声称其能
区分全部长尾参会人。若主讲指标失败，则超过4人的容量问题已经影响主讲，Earnings-22 不适合
当前固定前端。任何结果都不自动放行 Omni pilot。
